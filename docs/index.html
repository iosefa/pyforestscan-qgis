PyForestScan for QGIS

Forest structure tools in the Processing Toolbox. Plugin 0.3.3, experimental internal release; QGIS 3.40–3.x and 4.x; bundled PyForestScan 0.4.1.

Select a saved point cloud already in your project, add height above ground, and create forest metric rasters. Tools use normal Processing dialogs, batch jobs, and models. This help is included in the plugin and works offline.

Installation

Install pyforestscan_qgis.zip through Plugins → Manage and Install Plugins → Install from ZIP, enable PyForestScan, then open Processing → Toolbox. Double-click Check PyForestScan Dependencies, then click Run before your first analysis. Read the Log tab or open the generated HTML report in Processing → Results Viewer. If the overall status is OK, start using the forest tools. If the selected workflow needs the optional engine, follow the setup steps below. Restart QGIS after upgrading the plugin.

The ZIP includes the complete pure-Python sources of PyForestScan 0.4.1 and laspy 2.7.0, their licenses, and this offline help. Native processing uses QGIS's PDAL Processing provider, NumPy ≥2.3.1, SciPy ≥1.16, and GDAL Python bindings. It does not need Python PDAL bindings. Native point-cloud workflows require QGIS 4.2 or later for attribute-preserving export and bounded EPT reads. Older versions and statistical outlier cleaning use the optional engine. Capabilities are checked per workflow.

QGIS 3.40 is the minimum declared version. QGIS 4.x uses the same ZIP. Compatibility metadata through 4.99 does not mean every minor version has been tested; see the included test documentation for the recorded scope. The repository's environment.yml is for developers and tests, not required for community installation.

Optional engine setup

If Windows setup in 0.3.0 failed with [WinError 3] inside mamba\pkgs\file\..., install the current ZIP, restart QGIS, and click Install engine again. Setup reuses verified downloads and handles long cache paths. Existing working engines can continue to be used; no registry change is needed for this correction.

  1. Open Plugins → PyForestScan → Set up PyForestScan. The dialog reports native capabilities and the private engine's status, location, download size, and free-space requirement.
  2. Click Install engine. Keep QGIS open while packages download and the installation is tested. The first installation requires an internet connection; cancellation leaves any previous working engine available.
  3. When setup reports that the engine is ready, rerun the Processing tool. Leave Processing backend on Automatic to use QGIS when it has the required capabilities. If QGIS cannot read a particular source, choose Isolated engine to retry with the private PDAL reader.

No terminal commands or administrator installation are required. The engine contains its own Python and scientific libraries under your user data directory. Exact package downloads use HTTPS and SHA256 verification. A real HAG, metric, and raster self-test must pass before activation. QGIS's Python, other environments, and shell settings are not changed. On macOS, setup restores code signatures invalidated by package relocation inside this private environment.

Packages are provided for macOS Apple Silicon and Intel, Windows x64, and Linux x64. ARM Windows/Linux engine packages are not provided. Availability of a package manifest is distinct from end-to-end platform validation; consult the test record. The native workflow can still work on platforms without an engine package if its capability checks pass.

Use Repair engine for a broken installation. A replacement is built separately and becomes active only after validation; a failed repair preserves the current working engine. Remove engine removes only this plugin's owned engine installations and retains verified downloads for reinstall. Point clouds and projects are unaffected. An installed engine can process local data offline. Network proxies and certificates configured in QGIS are used for setup downloads.

First layer workflow

  1. Add a LAS/LAZ/COPC or EPT point cloud to the Layers panel. Check its CRS and classification.
  2. Open Add Height Above Ground, choose the point cloud layer, and select Delaunay or a DTM. Save a new LAS/LAZ file and enable QGIS's option to load the result.
  3. Open a forest metric such as Canopy Height Model or Plant Area Index. Choose the new point cloud and the existing-height HAG option. Set the XY grid and vertical bin sizes in metres.
  4. Save the GeoTIFF and load it into QGIS. Use normal raster symbology, statistics, layouts, and downstream Processing tools.

Metric tools can calculate HAG during a run. Use the separate HAG tool to keep the point dimension for inspection and reuse. Normalizing height adds HeightAboveGround; the source elevation Z remains elevation.

Shared inputs, coordinates, and cropping

InputHow to use it
Point cloud layer
INPUT_LAYER		Choose a saved point cloud from the project. The algorithm reads its underlying data source. Renderer settings and viewport clipping do not filter the input; layer subsets or unsaved changes that cannot be reproduced from the source are rejected.
Source path or URL
INPUT		Alternative to the layer selector: local LAS/LAZ/COPC, local ept.json, or HTTP(S) EPT URL. Leave this empty when choosing a layer. Supplying both inputs is an error.
Missing source CRS
INPUT_CRS		Only needed if the layer/data metadata has no CRS. This assigns a CRS; it does not transform coordinates. Conflicting known CRS information must be corrected in the source. The project CRS is never silently substituted.
Extent
BOUNDS		Restrict the processing area explicitly. QGIS transforms an extent with a known CRS into the point-cloud CRS. An extent without a CRS must already be in source coordinates.
Crop polygon
POLYGON		Choose a polygon layer or feature source. Geometries are transformed to the cloud CRS. Use Processing's Selected features only option to limit the crop to a selection; otherwise all supplied features are included.
HAG method
HAG_METHOD		Metric options: existing HeightAboveGround (0), Delaunay (1), or DTM (2). Existing heights must be present as a point dimension. Selecting Delaunay does not classify ground points.
DTM
DTM		A terrain GeoTIFF covering the processing area in the cloud CRS, with compatible metre elevations and vertical reference. Choose it only for DTM-based HAG. Reproject the DTM beforehand if necessary.
Grid sizes
VOXEL_XY, VOXEL_Z		Positive XY cell size and vertical height-bin size in metres. Finer bins increase memory use. Height thresholds are metres, not bin indices.

Forest metrics require a projected CRS whose horizontal units are metres. Z, DTM elevations, and HAG must also be in metres and use compatible vertical references. A CRS label cannot convert feet to metres or fix a vertical datum mismatch. Reproject or convert the data with appropriate QGIS tools before analysis.

Each single-metric raster tool returns a typed OUTPUT GeoTIFF destination. Use the standard Processing option to load it after completion, or connect the output directly to another model step. Choose persistent paths for outputs you want to retain.

Add Height Above Ground

pyforestscan:addheightaboveground

Creates a new LAS/LAZ containing a HeightAboveGround dimension. Choose Delaunay to build the terrain surface from points classified as ground (Classification == 2), or DTM to subtract an existing terrain raster. Delaunay requires at least three ground points that are not all on one line, with enough coverage to support the requested area. Explicit cropping also limits the ground points used. DTM requires valid band 1 terrain values at every processed point.

The new file retains other point dimensions and can be loaded as an ordinary QGIS point cloud. LAS/LAZ/COPC inputs preserve their native XYZ precision; EPT coordinates are serialized at the precision supported by the output LAS encoding. Elevation Z remains elevation and is not replaced by normalized height. It does not edit the original layer in place. Choose a different output path from the source. This tool writes LAS/LAZ, not COPC; QGIS may index the new file when loading it. Use this output in later tools with the existing-height HAG option, or style its HAG attribute in QGIS.

Canopy Height Model

pyforestscan:canopyheightmodel

Writes the maximum height above ground in each XY cell as a single-band GeoTIFF, in metres. The cell size determines the spatial detail. Empty cells remain NoData.

Interpolation is disabled because the pinned library's interpolation path has a grid-coordinate issue. If your analysis calls for gap filling, apply an explicit QGIS raster interpolation/fill step to the result and record its settings. Filled gaps are estimated heights.

Plant Area Density (PAD)

pyforestscan:plantareadensity

Bins returns horizontally and by height, then estimates PAD with the PyForestScan Beer–Lambert method. The library's PAD constant is 1, and the actual vertical bin height is supplied to the calculation. PAD has units of plant area per volume (m²/m³).

The output is a multiband GeoTIFF. Band 1 is the lowest height interval beginning at 0 m; later bands proceed upward by VOXEL_Z. Band metadata records the intervals. The lowest ground bin is excluded from PAD and may be entirely NoData. Missing/undefined attenuation values are also NoData.

In QGIS raster symbology, choose a band to inspect that height slice. This raster preserves the vertical profile; PAI is the separate tool for integrating that profile into a 2D canopy measure. PAD is no longer exported as NPZ.

Plant Area Index (PAI)

pyforestscan:plantareaindex

Integrates PAD above the chosen minimum height using the actual vertical bin height. The result is a single-band GeoTIFF in m²/m², a dimensionless area ratio. A minimum height of 1 m means 1 metre above ground, independently of bin size.

Thresholds select whole height bins according to the core method. Use consistent vertical bin sizes and thresholds when comparing areas. An empty integration interval can return zero; a column with no valid PAD in a nonempty interval is NoData.

Foliage Height Diversity (FHD)

pyforestscan:foliageheightdiversity

Calculates Shannon entropy of the proportions of returns among vertical height bins for each XY cell. The minimum height defaults to 0 m. The output is a dimensionless single-band GeoTIFF in natural-log units. A larger value indicates returns distributed more evenly across height bins; it does not directly measure species diversity.

Changing vertical bin size changes the number of possible bins and can change FHD. Compare results with the same grid and height settings. Cells with no returns in the included range are NoData.

Canopy Cover

pyforestscan:canopycover

Calculates canopy cover from PAD using cover = 1 - exp(-k × PAI_above_threshold). The minimum height defaults to 2 m and extinction coefficient COVER_K defaults to 0.5. Output values are fractions between 0 and 1; multiply by 100 in a raster expression to display percentages.

This is a PAD-derived Beer–Lambert estimate, not the fraction of point returns above the height threshold. The canopy-cover extinction coefficient is distinct from the PAD calculation's constant of 1. Both the definition and results differ from plugin 0.1.1.

Forest Voxel Statistics

pyforestscan:voxelstatistics

Summarizes a chosen point dimension over each XY column. Enter an existing dimension name such as HeightAboveGround, Intensity, or Z, and choose mean, sum, count, minimum, maximum, median, or standard deviation. Dimension names must match the source.

The output is a 2D single-band GeoTIFF, not a 3D cube. Statistics use the selected dimension's units; count is a number of points, and standard deviation uses the population definition. Count and sum can be zero in empty cells; other statistics use NoData. HAG is required to place points in the height grid even when summarizing another dimension.

Rumple Index from CHM

pyforestscan:rumpleindex

Select a loaded, local, north-up CHM raster and its height band (band 1 by default). An optional minimum-height threshold masks lower cells. The algorithm calculates the ratio of triangulated canopy surface area to planar area over valid adjacent 2×2 raster patches. It returns a CSV report as OUTPUT and a numeric RUMPLE output for models.

Use a projected metre CRS and heights in metres. At least one complete valid 2×2 patch is required. Rotated rasters must first be warped to a north-up grid; rasters above 20 million cells must be clipped before this in-memory calculation. A flat valid surface has rumple 1; increasing roughness increases the ratio. NoData, threshold masking, raster resolution, and gap filling affect which patches contribute and the resulting value. This is one summary for the input raster, not a per-cell rumple raster.

Legacy combined algorithm

pyforestscan:calculatelidarmetrics

Since 0.3.2, Calculate Forest Metrics is hidden from the toolbox and model builder. Existing models and scripts can still call its unchanged algorithm ID. Use the focused forest tools for new workflows. The following describes the compatibility interface.

Calculates several outputs from one point-cloud read. Select CHM, PAD, PAI, FHD, canopy cover, point density, rumple, or voxel statistics and choose an output folder. LOAD_OUTPUTS controls whether rasters are added to the project. Existing metric files are protected unless OVERWRITE is enabled. Individual outputs have Processing types so models can consume the selected results.

The first seven metric indices are retained for existing scripts: CHM 0, PAD 1, PAI 2, FHD 3, canopy cover 4, point density 5, rumple 6. Voxel statistics is appended at 7. The algorithm ID remains stable, but corrected calculations and the dependency upgrade mean numeric equivalence to 0.1.1 is not promised.

PAD is now pad.tif, with height bands. Point density counts retained returns per square metre; points with negative/nonfinite HAG are excluded, so it may differ from a native density of every source return. Rumple is reported in CSV. The single-metric tools are convenient when building a model with one named output per step.

Process EPT Tiles (advanced)

pyforestscan:processepttiles

Processes a local or remote EPT dataset in tiles for CHM, PAI, FHD, or canopy cover. Select an EPT point-cloud layer with INPUT_LAYER, or enter its ept.json path/URL with EPT_INPUT. Use only one source input. SRS assigns missing CRS information; it does not reproject a known source.

Choose a processing extent, tile width/height, XY resolution, vertical bin size, and HAG method. Buffered reads give HAG computation surrounding terrain support; points are then restricted to each core tile for metric output. Tile width and height must be whole multiples of the XY cell size, and the output extent is snapped outward to that common grid. Only points inside the study area contribute to metrics; edge cells may extend beyond it. Empty tiles are skipped. Tiled CHM uses maximum HAG through the core voxel-statistic function.

Tile dimensions must be whole multiples of the XY cell size. Extents snap outward to that grid; points are clipped to the requested extent, but edge pixels may extend beyond it. Cells without retained points are NoData. A DTM must cover the buffered read area as well as the core tile. Existing tile files require explicit OVERWRITE; only files created in this run are returned.

The tool writes a folder of GeoTIFF tiles and returns a list of raster outputs. Enable LOAD_OUTPUTS if you want every tile loaded; this is off by default to avoid filling the Layers panel. Use QGIS raster tools to build a virtual raster or mosaic. No automatic resampling or mosaic is performed.

Optional outlier cleaning requires the isolated engine and affects the points contributing to metrics. Existing tile files cause an error unless OVERWRITE is enabled. Cancellation is checked between stages and during engine jobs. Completed tiles remain on disk after cancellation; incomplete writes are not published. A forced stop can leave a hidden staging file in the output directory. Start with a small extent to confirm resolution, terrain coverage, memory use, and temporary disk space.

Check PyForestScan Dependencies

pyforestscan:checkdependencies

Double-click this tool to open its Processing dialog, then click Run. Leave PyForestScan dependency report set to a temporary file, or choose an HTML destination to keep. Results appear in the Log tab and in an HTML report accessible through Processing → Results Viewer; double-click the report to open it. Versions through 0.3.2 could run silently from the toolbox because this tool had no visible parameters. It is not deprecated.

Reports QGIS's native capabilities, bundled PyForestScan version, selected backend, and the optional engine's status. If an engine is installed, it runs a real HAG, metric, and raster self-test. With Automatic selected, overall status is OK when the native workflow is available or the installed engine passes its test. With Isolated engine selected, that engine must pass. Missing native capabilities can therefore appear alongside an overall OK status when the engine supplies them. Individual tools check their own requirements when run. Scripts and models retain the text STATUS output and now also receive the HTML REPORT path.

This tool reports issues; it does not install packages. Use PyForestScan setup to install or repair the private engine. A successful check does not validate a point cloud, its classification, vertical reference, or remote access. Test a small representative crop before a large run.

Interpretation and practical limits

Native processing uses temporary uncompressed LAS files, so allow disk space beyond the compressed input size. Single-area tools read points into memory. Metrics exclude negative/nonfinite HAG and report exclusions in the log; nonfinite source coordinates are rejected during input validation. Voxel volumes grow with footprint, maximum height, and finer XY/Z bins. Crop to the area you need and choose grid sizes appropriate to the data; use EPT tiling for large EPT sources. Dense grid allocations are limited to five million cells/voxels, including voxel overflow bins; exceeding this limit requires a smaller area or larger cells. This limit is not a cap on the memory used to read source points.

QGIS's native LAS export can quantize floating-coordinate EPT data to 0.01 m. Select Isolated engine in setup for EPT metric calculations requiring finer source precision. LAS/LAZ/COPC inputs keep their stored coordinate scales. Persistent HAG outputs from EPT still use LAS coordinate encoding.

NoData means the metric could not be evaluated for that cell/range. It is not interchangeable with zero. Inspect spatial coverage and the Processing log before interpreting an output. Keep resolution, height thresholds, coefficients, and preprocessing consistent across comparisons. Single-area CHM and voxel metrics can use different grid origins even at the same resolution. Inspect their georeferencing and align rasters explicitly in QGIS before combining cells from different outputs.

Use QGIS for general point-cloud filtering, clipping, reprojection, ground classification where a suitable provider is installed, raster conversion, mosaicking, and visualization. The plugin's focus is HAG and forest structure. The included API coverage inventory accounts for every public PyForestScan 0.4.1 function, including utilities available only through Python or equivalent QGIS workflows.
